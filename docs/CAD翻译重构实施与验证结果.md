## 实施结论

保留当前 CAD 原生翻译架构，按已批准的范围重构。收益集中在消除真实误报、导入前发现文字错误、保留已完成工作、局部修正和避免重复渲染，没有扩大排版搜索或叠加人工审批。用户仍只需给文件、目标语言和替换/双语要求，AI 负责翻译、恢复、修正和视觉验收。

修改前已有的 23 个文件改动先独立保存在 `c6dd8e7`，便于与本次重构区分。主分支仍为 `728ef9f`；未覆盖挂载技能、生产插件或用户原图。测试采用受信任目录中的独立分支 DLL。

## 本次实际改动

| 项目 | 解决的问题 | 质量与时间影响 |
|---|---|---|
| Core 统一文字校验 + 无 CAD 的 CLI | Python 通过后才在 CAD 中发现数字/控制码问题；图号和字距码误报 | 图号、型号、单位仍受保护，CAD 启动前一次给出具体错误行 |
| 结构身份校验 | DWG 保存清理无引用匿名块、重编号匿名块名称导致误报 | 仅排除无引用匿名实现块；保留命名库、活动块及定义关联；真实移动、删除、跨匿名块交换仍拒绝 |
| `resume` | 已保存候选因后置检查失败而整图重跑 | 绑定源图、语言/模式、清单、译文和候选；只补缺失工作，已有候选复查后继续 |
| 局部译文恢复 | 少数缺失或错误记录导致正确译文重复处理 | 保存有效行，只生成需要修复的工作单元；完整但含错误的批次同样支持局部修复 |
| `correct` | 两个文本排版问题需要临时开发脚本或全量导入 | 一次事务调整已存在译文的宽度/字号/位置，保存新候选；完整内容、原图和旧候选保留 |
| 渲染复用 | 相同图纸/窗口重复启动 CAD，已有文件导致报错 | 图纸、窗口、视图、渲染器、图片摘要一致才复用；变化时生成新版本并保持配对 |
| Skill 流程覆盖更新 | 旧文档要求原生失败一律新建任务，缺少可执行局部修正命令 | 用同任务恢复/修正替换旧流程；继续由 AI 完成语义和视觉判断 |
| 分段计时与运行身份 | 无法快速定位耗时阶段或确认加载的 DLL | 双语阶段拆分记录；运行保存 DLL 指纹；避免依据过夜等待时间误判性能 |

## 有意保留的边界

- `correct` 是已有译文的几何调整接口，不改写译文，也不补建缺失标签。内容变化需要修复批次并进行新的绑定导入；缺失标签需处理原有放置失败原因。禁止用更改回执摘要代替验证。
- 旧版替换候选若已合并段落且没有内容回执，可能需要一次新导入；不会仅凭旧句柄映射宣布完整。新候选保存内容回执支持后续复查。
- 局部修正后必须重新检查涉及的视图及概览；自动几何复查并不等于视觉合格。可读的小幅换行/对齐差异仍可由 AI 记录告警后交付。
- 本次没有做新的模型翻译质量排名或大样本完成率统计。证据支持减少误报、保留工作及防止具体错误，不能宣称所有图纸的语义质量或端到端时间提高某个百分比。
- 继续保留已有 AutoCAD SDK 引用警告及旧原生测试可空性警告；本次构建无错误。未为消除无关警告扩大重构范围。
