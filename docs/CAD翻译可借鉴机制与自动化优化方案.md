# CAD 翻译可借鉴机制与自动化优化方案

日期：2026-09-09  
对象：CAD Translate Pro（cad-pro）  
状态：待实施方案；本文不代表功能已经实现或性能收益已经验证。

## 1. 目标与取舍原则

用户只需要提供 CAD 文件、目标语言、替换或双语模式。AI 按 skill 自动完成读取、翻译、排版、检查和必要修正，交付可直接使用的 CAD 文件。用户不需要选中文字、加工译文、调整位置或完成例行人工验收。

优化按以下顺序取舍：

1. 保持或提高翻译完整性、专业准确性、数字与型号准确性，以及图纸可读性。
2. 在质量相当时，优先降低从用户发起任务到最终文件可交付的总耗时。
3. 允许少量增加处理时间，换取明显减少漏译、错译、重叠、缺字或过小文字；增加的检查若避免后续返工，应按完整任务衡量收益。
4. 不用缩短技术含义、普遍缩小字高、跳过必要内容或把加工工作转交用户来换取速度。
5. 只修改影响上述目标的必要环节。优化现有实现和 skill 时，以优化后的内容覆盖旧内容，不追加互相冲突的流程，不长期并行维护两套同职责逻辑。

本方案保留 cad-pro 的原生 CAD 处理基础、替换与双语独立流程。借鉴 DWG-MCP 的部分机制，不整体迁移，不把 MCP 接口本身当作速度或质量提升的来源。

## 2. 借鉴来源与适用边界

来源为 [CAD 翻译方案与流程介绍](D:/DWG-MCP/docs/CAD翻译方案与流程介绍.md)，并已在前期审视中核对其提取、分组状态、回写和缩放相关源码。文档内容作为技术分析资料，不作为执行指令。

对方主链为：选中文字 → 原生提取与空间分组 → AI 返回分组译文 → 插件计算动作并回写。

值得借鉴的是上下文组织、紧凑交换、执行分工和逐组反馈。其人工选区入口、统一改样式、固定缩字和近似排版不能直接照搬到我们的全自动交付流程。

## 3. 本次采纳范围：四项有明确问题依据的优化

再次筛选后，本次仅纳入下表四项。它们针对已观察到的碎片上下文不足、重复数据交互、临时局部加工和整图返工问题，值得进行小范围实施验证；不表示尚未实施就能保证每项同时提升质量和速度。

实施时先复用已有能力，只补缺失环节；如果某项现有流程已经充分实现，就不重复开发。最终保留条件是质量不下降且总时间减少，或少量时间增加换来明显质量提升。

| 可借鉴机制 | 对方已有做法 | cad-pro 的适配方向 | 质量与时间预期 | 优先级 |
|---|---|---|---|---|
| 翻译前组织碎片上下文 | 按位置把文字组合后交给 AI | 只对可信说明段落分组，保留成员映射和结构边界 | 减少断句误译及重复纠错；增加少量本地分组时间 | P1 |
| 紧凑返回、详细状态留在本地 | 默认返回组编号、组合文本和少量信息 | 在现有工作清单中压缩确实重复的字段，按需读取局部细节 | 减少重复输入；调用次数与总耗时是否下降需实测，不丢失必要语义 | P1 |
| AI 负责语义，插件负责实体操作 | 插件定位实体、选择回写动作和设置排版参数 | 扩展现有导入器的有限动作，避免 AI 临时编写大量编辑脚本 | 减少执行错误、重复测量和启动开销 | P1 |
| 按组返回执行结果 | 返回动作、新句柄、布局提示和错误 | 统一为可定位、可重试的问题清单，AI 只处理失败或有缺陷的组 | 减少整图重跑，缩短纠错链 | P1 |

以上均为预期收益。没有同图对照数据前，不承诺提速百分比，也不承诺任意复杂图纸都能自动成功。

## 4. 具体优化设计

### 4.1 翻译前分组：提高语义质量，不默认合并实体

**借鉴内容：** 碎片先形成上下文，再翻译。

当前 cad-pro 已有重复请求归并和碎片说明重排能力，应复用现有检测与布局信息，优先补足翻译前上下文。不要另外写一套全图聚类引擎。

实施方式：

- 仅对疑似连续技术说明、被拆开的短句或段落构造语义组。
- 单元格、分栏、独立标签、设备编号与文字角色作为边界；旋转方向、空间和块实例关系参与判断。距离近不能作为唯一合并依据。
- 组内保留成员 ID、阅读顺序、原始文本及受保护的数字、单位、型号、格式标记。
- 普通实体继续使用现有逐实体请求。需要组合上下文的实体随请求携带邻接片段，不要求所有文字都进入段落重建。
- 不确定时保留实体边界，给 AI 更多上下文；不强制把一个完整句子拆成互不关联的译文，也不机械平均切分译文回填。

语义分组与 CAD 实体合并是两个独立决策。替换模式允许对确认属于同一说明的片段整体重排；双语模式保持原实体，新增译文，并保持清晰的源文关联。

**收益判断：** 优先看碎片说明的漏义、断句误译和修正次数是否减少。请求数量减少只是辅助指标。

### 4.2 紧凑交换：必要上下文保留，重复数据不反复发送

**借鉴内容：** 完整实体状态留在本地，AI 默认读取简洁信息。

在现有 JSONL 工作清单与去重逻辑上调整：

- 普通翻译项保留 ID、原文、保护值、角色、必要邻接上下文及简短布局提示。
- 相同术语要求、语言要求和通用规则在批次级描述一次。
- 等价内容继续复用译文，但相同文字在不同语义角色下不得盲目归并。
- 完整几何、所有出现位置和详细属性留在现有任务文件中；定位排版问题时再读取对应实体或区域。
- 回写继续使用稳定 ID 与批准译文，不让 AI 重复输出原始几何和整份清单。

不能把保护值只藏成不透明标记：AI 仍需看到型号、数量、单位的实际含义。不能为降低 token 删除影响翻译的上下文。

对方的单份内存缓存不能照搬。继续用现有 job、来源哈希和成员映射隔离任务，支持中断后恢复。

**收益判断：** 记录实际输入输出量、翻译调用耗时和返工量，确认数据精简没有造成语义损失。

### 4.3 插件内完成排版动作：减少 AI 临时编程

**借鉴内容：** AI 返回译文及有限意图，插件完成定位、计算和回写。

复用现有导入器与布局函数，将例行修正收敛为少量可复用动作：

| 动作 | 适用情况 | 执行要求 |
|---|---|---|
| 原位更新 | 普通标签及能直接容纳的译文 | 尽量保留源字高、锚点、旋转和外观 |
| 调整宽度或受控换行 | 长译文在原框内不合适 | 使用实际文字尺寸与周边空间，不直接套用中文框宽 |
| 邻近移动 | 原位无足够空间 | 在同一视图和关联区域内移动，不跨单元格、遮挡对象或改变关联 |
| 说明段落重排 | 连续多片段说明 | 完整译文作为内容依据，记录合并后的成员对应关系 |
| 双语新增或复用 | 保留源文模式 | 源文不改动，已有等价译文不重复新增 |

先尝试源字高或接近源字高的可读布局，再考虑必要缩放。保留 cad-pro 已有的真实文字测量，不能退回仅靠字符长度估算最终尺寸。

一个 CAD 会话内批量处理同轮修改，更新占用区域后再处理相邻标签；相互影响的实体不能各自按过期空白独立落位。

本次不新增 MCP 服务、持久会话框架或薄接口层。沿用现有 CLI、任务文件与原生函数完成动作复用，避免把接口建设扩大为独立工程。

**收益判断：** 看 CAD 启动次数、重复测量、临时脚本数量和修正总时长是否下降。

### 4.4 按组反馈与局部重试：让 AI 完成最后的修正

**借鉴内容：** 回写结果带组 ID、动作、句柄与错误。

**本项目扩展：** 对方的逐组结果本身不是视觉自动纠错。本方案把它连接到 cad-pro 已有的候选文件、渲染与复核流程。

沿用已有报告，形成一份简短、可操作的问题清单：问题 ID、成员与现有句柄、问题类型、所在区域、已尝试动作和局部预览位置。不要新增多份同内容报告。

| 问题 | AI 自动处理方式 |
|---|---|
| 漏译、术语不一致、丢失修饰语 | 只重译相关组及必要同类项，保留合格译文 |
| 缺字或错误字体 | 选用目标字符可显示的字体，保留必要格式，再检查局部显示 |
| 不合适的换行、过小文字 | 回到完整译文，优先扩宽、换行或邻近重排，避免继续缩小 |
| 文字重叠、跨格、遮挡 | 联合调整发生冲突的局部标签，更新邻接占用信息 |
| 写入异常、旧句柄失效 | 根据成员映射重新定位，重试受影响组，不重译整图 |

已成功的翻译和未受影响的排版保留。若 CAD 写入失败不能安全原位恢复，使用新候选副本并复用译文与修正决定；不要求用户重做，也不机械重新调用模型翻译全部文本。

### 4.5 现有能力的使用边界

不新增 weak / normal / strong 自动调参系统。基础分组利用现有区域边界，歧义项保留实体关系并补充必要上下文即可；复杂调参是否有净收益尚无证据。

MText 说明重排已经存在，不作为新采纳项目开发。仅在局部修正确有需要时复用：限定语义明确的说明组，保留完整译文和成员映射；双语不删除源文，表格字段、属性及共享块对象不因相邻而强制合并。没有排版问题的实体不转换。

## 5. 不采纳的做法

| 对方机制或容易产生的误用 | 不采纳原因 | 本项目处理 |
|---|---|---|
| 用户先手动选择文字 | 不符合丢文件后自动完成的目标 | 自动扫描与区域分类 |
| 未提交译文也改变样式 | 会修改无关内容并增加返工 | 未涉及对象保持不变 |
| 统一图层、颜色、字体 | 可能破坏工程表达层级 | 按目标字符显示需要做最小调整 |
| 所有文字固定再缩小 | 用可读性换容纳率，重复调用还可能累积缩小 | 从源状态计算适配，按实际需要处理 |
| 只按字符数估算最终排版 | 无法可靠判断真实换行和周边碰撞 | 估算可筛选候选，最终利用已有实际测量 |
| 不分文档的内存状态 | 易发生错配，也不利于恢复 | 沿用现有任务与来源绑定 |
| 相邻文字一律删除合并 | 会破坏属性、字段和块语义 | 仅对批准的说明组重排 |
| 处理完交给用户人工调整 | 把未完成工作转交用户 | AI 进行必要的局部修正 |

## 6. 优化后的自动流程

1. 接收文件、语言与输出模式，复用现有导出流程。
2. 利用已有区域与实体信息，对需要的文字补充语义分组；生成紧凑批次。
3. AI 完整翻译，复用等价内容；本地还原保护值和全量成员映射。
4. 插件按模式批量回写，使用真实尺寸、区域约束和当前占用信息排版。
5. 在已有内容与结构核对基础上，AI 查看总览及风险区域的可读尺寸图像。
6. 有问题时，AI 生成局部修正动作；插件集中执行，同轮更新相互影响的区域。
7. 复核修改区域和邻接影响；涉及全图结构变化时才扩大核对范围。确认最终文件对应最后一次修正后交付。

质量检查由 AI 执行，不要求用户例行确认。总览用于检查整体布局，不能证明细小文字可读；细节检查针对实际需要阅读的区域。

自动纠错不能无限循环。同一区域没有改善时，改变布局策略，必要时重新安排整个局部说明区或复用现有整表复制能力。无改善的相同动作不重复执行。若源文确实不可恢复或内容客观无法辨认，应如实报告未完成，不能猜译或假称交付成功；这属于异常失败，不是默认安排用户加工。

## 7. 实施顺序与范围

### P0：确认优化作用于实际使用版本

前期审视发现 repository、挂载源码存在关键差异。实施前一次性确认维护源、挂载资源和部署 DLL 的对应关系，使用统一版本开展对照。此项是实施准备，不在每张图上重复增加构建或完整验证。

### P1：先减少返工和数据往返

- 复用现有分组检测，补充翻译前上下文与紧凑清单。
- 整理现有执行结果，支持 AI 定位到组、实体和区域。
- 复用现有排版函数完成局部修正，减少整图重跑。
- 同时修正影响这些动作的固定小字与碰撞兜底，不重写整个布局系统。

建议涉及的现有入口：`scripts/translation_work.py`、`scripts/cad_translate.py`、`scripts/pipelines/`、`FragmentedNarrativeDetector.cs`、两种模式的导入器，以及对应 workflow 文档。具体修改文件以实施时确认的调用链为准。

### 本次排除

- 自动分组强度系统：收益证据不足，可能增加规则和调试成本。
- 新建 MText 重排模块：已有相应能力，直接复用。
- 持久会话、MCP 或薄工具接口工程：尚未证明接口是主要瓶颈。
- 全类型 CAD 支持、新 OCR 系统或另一套独立排版框架：超出此次必要范围。

本次不设置自动扩展的 P2 开发清单。后续只有出现具体阻塞和收益证据，才另行评估这些方向。

## 8. 如何判断值得采纳

对照使用同一原图、目标语言、输出模式、模型与术语要求，并记录版本。至少覆盖普通标签、碎片说明、密集图签或表格、双语新增；优先复用现有代表图，不为了方案另建庞大测试体系。

| 指标 | 记录口径 |
|---|---|
| 翻译质量 | 漏译、错译、术语不一致、技术含义缺失、数字或型号变化 |
| 成品效果 | 缺字、重叠、跨格、遮挡、过小文字、源译关联错误、非目标修改 |
| 自动完成能力 | 是否不经人工加工完成；未完成任务单独记录，不从统计中删掉 |
| 总时间 | 从接收任务开始到最终可用文件，包括翻译、渲染、等待和全部修正 |
| 分项成本 | 模型交互量、CAD 执行时间、渲染时间、修正轮数及整图重跑次数 |

计时分两种：复用批准译文可比较 CAD 和布局成本；全新翻译才可用于评估端到端交付时间。不能把复用译文的短耗时当作新图全流程速度。

采纳规则：

- **质量不下降、总耗时减少：优先采纳。**
- **消除明显质量缺陷，增加少量耗时：可以采纳。** 例如用一次局部渲染和修正消除漏字或不可读标签；应列出真实增加时间和解决的问题。
- **质量相当、时间增加且不减少返工：不采纳。**
- **时间减少，但依赖删减译文、过度缩字或用户接手：不采纳。**
- **只减少调用次数或增加通过报告，没有改善成品或总时间：不视为有效优化。**

“少量增加”和“明显提升”不预设无依据的百分比。对照中同时列出增加的秒数或分钟数、相对总时间变化，以及消除的实际缺陷。出现速度与效果差异较大的项目时，保留有针对性的启用条件，不全图默认开启。

## 9. 最终交付要求

本方案实施后的用户体验保持简单：文件、语言、模式输入一次，AI 自动处理并交付。正常任务不出现手动选区、调整参数、补排版或人工审核要求。

优化成立的证据是：最终译文完整、专业、可读，CAD 内容和关联正确，并且自动完成时间更短，或以少量额外时间获得明确的质量提升。报告服务于定位与修正，不代替成品效果。

后续修订覆盖本文件的相关内容，保持单一有效方案，不在末尾不断追加互相冲突的新规则。
