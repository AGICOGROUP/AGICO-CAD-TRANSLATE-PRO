# CAD 翻译重构评审方案

日期：2026-09-11  
状态：当前版本重新分析后的评审稿；尚未创建重构分支、修改业务代码或部署。

## 1. 重构目标

用户提供 CAD 文件、目标语言和替换／双语模式，AI 自动完成并交付可使用的文件。以现有初步达标的效果为基础，提高技术翻译质量与视觉效果、容错能力和完成率，减少报错、重复工作和总耗时。

优先消除导致失败和返工的根因。允许少量增加局部处理时间以显著提高效果；不以丢失内容、误改数字、过度缩字或用户接手加工换取完成率。不追求所有细节绝对完美：保留当前可用成品带轻微瑕疵交付的机制。

这次是针对当前系统的重构，不再受之前四项借鉴清单约束。旧的借鉴方案属于前期参考，本稿作为本次评审依据。

## 3. 发现的问题与证据边界

### A. 前置校验与原生校验规则不一致，部分技术标记解析有误

已直接调用当前 Core 复现：

| 源文 | 译文 | 当前结果 |
|---|---|---|
| 图号09 | Drawing No.09 | 数值／型号一致性检查失败 |
| 图号09 | Drawing No. 09 | 通过 |
| 图号09 | Drawing No. 10 | 正确拒绝 |

对应 DWG11 r2 保留批次中的 1697 条记录可以通过当前 Python `validate_complete_translations`，而原生导入报告将三个 `Drawing No.09/04/05` 列为 `numeric_or_protected_token_mismatch`。

当前 Core 的模式会把字母加数字的串识别为型号，普通图号表达因边界不同产生误报。另直接确认 `\T1.001;` 未被整体识别为 MText 格式控制码，而将 `T1.001` 识别为型号；`预埋钢板δ20,5块` 的 `20,5` 被打成一个数字 token，混淆尺寸与数量分隔的风险需要结合原图语义处理，不能自动假定所有逗号都是小数点或分隔符。

影响：模型需要无谓调整文本，校验错误在 CAD 阶段才暴露，且保护机制不能正确表达部分技术语义。

### B. 结构比对持续阻塞完整交付，当前差异信息不足以定位原因

DWG11 r3、r4、r5、r6 均在保存后结构检查失败。四次导入分别约 911、914、1063、891 秒，合计约 63 分钟；这是保存的四次 CAD 导入时长，不含翻译和其他尝试，也不是平均用户任务耗时。

当前结构比较按排序后的签名行寻找第一个不同项。示例甚至将不同类型或位置的实体列在 expected／actual 两边，因此不能把第一对不同的行理解为“同一实体被移动”。

已确认问题在最终结构比对阶段暴露；尚未证明是匿名块保存重编号／重生成、提取坐标不稳定，还是真实几何变化。不能通过统一忽略匿名块、扩大数值容差或取消检查来解决。

### C. 重试主要靠 AI 重新组织命令，缺少稳定的恢复与局部修正入口

现有 CLI 有 export、prepare、assemble、import、audit-summary、status。`--retry-from` 继承计时，不恢复 CAD 阶段。skill 仍要求新原生尝试建新 job，并由 AI 转移符合条件的译文、重新编排步骤。

已有一些自动局部修正，但没有覆盖两种模式常见问题的统一调用方式。最新 DWG11 修正仍有独立原生测试命令与临时任务产物，且局部生成成功未解决完整结构阻塞。

影响：小问题容易演变为整图导入重跑；成功的翻译、排版和渲染结果难以被流程自动复用。

### D. 搜索与重复读图存在压缩空间，但耗时分布尚未完整测量

源码可见多层字高、宽度、位置候选，以及对障碍物和块投影的反复处理；结构核对与候选提取还分别重新打开图纸。当前已经有部分邻近障碍筛选和批量渲染，应保留。

891 秒不能直接全部归因于某一个循环。需要在现有 timing 中补少量关键阶段耗时，区分拓扑、排版、保存和验证；只优化占比高的部分，不先建设复杂空间索引或持久会话框架。

### E. skill 规则丰富，但恢复步骤和职责仍分散

SKILL、分支流程和视觉复核中重复说明了重试、候选保留、检查和交付。Python 与 Core 对同类内容各自校验，且存在 `runtime=SimpleNamespace(**globals())` 等隐式依赖。

模型既要翻译、判断视觉效果，又要理解多个报告、判断失败在哪一层、临时选择恢复命令。应简化常规操作入口，把确定性的恢复工作放进代码；不让 skill 变成持续追加的故障手册。

## 4. 选择的重构方式

可选方式：

1. 继续按单个图纸报错追加补丁：短期改动小，但重复试错和规则分散继续存在。
2. 保留有效能力，重构文本规则、任务恢复和原生执行边界：直接覆盖当前阻塞，推荐。
3. 整体换引擎、迁移 DWG-MCP 或重写：迁移成本高，已有问题没有证据会自然消失，不采用。

推荐第二种。不是按文件大小机械拆分，而是让一项规则只维护一处、一次失败能回到正确阶段、一次修正只影响必要区域。

## 5. 六项重构工作

### 1）统一技术文本解析与校验

- 以现有 Core 文本规则作为权威实现，梳理自然语言、型号、数值单位、图号和 CAD 控制码的边界。
- 将纯文本校验放在 CAD 启动前执行，供 Python 编排调用；保留原生写入时的必要一致性确认，不再维护含义不同的两套规则。
- 自动修复仅限确定无歧义的格式问题。数值、符号或语义不确定时，将原文、保护值和上下文返回 AI 定点修正。
- 一次返回全部可定位错误，保留其他合格批次。错误信息包含实际原／译保护值差异，而非仅有通用错误码。

预期：直接减少数值／型号误报和晚失败，同时提高技术标记准确性。

### 2）修正结构核对的匹配方式与保存兼容性

- 先在分支内对 DWG11 做原图副本“仅打开另存、不翻译”的对照，区分保存自身变化与翻译造成的变化。
- 采用稳定实体身份与块关系进行差异匹配；匿名块重生成的处理以真实对照为依据，不把所有匿名块折叠成不可区分的一类。
- 对有差异的对象返回新增、缺失、属性或几何改变，以及可定位的块／实例上下文。
- 尽量复用同次打开的候选和源基线。修正结构规则时直接检查既有候选，不重新翻译和排版。

预期：减少误判和排查成本；如果对照证明真实损坏，则修保存／回写路径，不能放宽验收来提高通过率。

### 3）把 job 改成可恢复任务，减少整图重跑

- 保留现有 job 文件，整理为导出、翻译、原生写入、最终检查几个明确阶段，不另建工作流平台。
- 一个任务内保存独立尝试与候选版本，保持源文、译文和实际插件版本的对应关系。
- 提供一个恢复入口：读取现有状态，自动确定哪些阶段仍有效、哪些局部需要重做。
- 文本错误只修相关批次；布局错误保留内容，改局部；检查失败优先重查候选；仅在候选或阶段产物确实无效时重跑相关原生阶段。
- 对可恢复的对象／组级异常隔离处理并保留诊断；数据库、源文或结构损坏仍停止写入。程序错误不能无限自动重试。

预期：提高容错与自动完成率，减少命令组织、重复导出、重复翻译及重复排版。

### 4）将现有局部修正接入正常自动流程

- 保留两种模式独立的修改和验收规则，共用中立的问题定位与命令传输。
- 复用调整宽度、受控换行、邻近移动、成组说明排版和整表复制，提供有限的局部修正动作。
- AI 只返回问题对象、完整译文和布局意图；代码负责句柄定位、组关系、几何计算及写入。
- 同轮局部修正合并成一次原生执行；记录影响范围，更新邻接占用，不损坏原先合格区域。
- 统一普通与兜底路径的边界判定。保留当前源字高快速尝试，优先可读性；不要新增普遍缩字步骤。

预期：将现在部分依赖临时脚本的最后加工变成 AI 可稳定调用的流程，提高成品效果与完成率。

### 5）按真实耗时减少重复计算与渲染

- 在现有计时中记录拓扑、排版、保存、验证与渲染，定位最耗时环节。
- 复用当前候选的文字尺寸、区域与块投影；缓存随文字、样式、位置和候选变化失效，避免使用旧包围盒。
- 几何快速筛选放在真实文字测量前，合并等价布局候选；失败后切换有意义的布局策略，不反复遍历同样位置。
- 沿用批量渲染，合并相邻检查窗口，修改后只重绘受影响区域及必要总览；不能只看风险项而完全不检查整体覆盖和代表区域。

预期：降低计算和检查耗时。具体采用缓存、局部索引还是候选精简，以阶段测量结果决定，不预先承诺百分比。

### 6）覆盖式重写 skill 的操作流程

- 主 SKILL 只保留意图解析、一次标准流程、恢复入口、质量底线和交付方式。
- 替换／双语文档只保留各自有差异的行为；共通技术细节移入明确引用的代码接口或必要参考。
- 常规错误先由代码定位和恢复；需要语义或视觉判断的交给 AI。用户无需参与例行排版、参数选择或审批。
- 修正语言说明与当前中、英、西、法支持范围的差异，但不在本轮扩展新语言或全部 CAD 类型。
- 删除被替代的旧路径和重复说明，不追加一套“V3 流程”与旧流程长期共存。

预期：减少 AI 读规则、分析报告和临时组织步骤的时间，也减少流程执行不一致。

## 6. 精简后的任务流程

文件＋语言＋模式 → 导出并准备工作清单 → AI 翻译 → 统一文本检查与定点修正 → 原生布局与保存 → 内容／结构核对及 AI 视觉判断 → 必要的局部修正 → 交付。

出现问题时回到所需阶段，不默认回到开头。一般格式问题自动修，语义问题由 AI 修，图纸局部问题由原生动作修。无收益的重复动作停止，改用不同布局策略；真正无法完成时如实说明，不能把草稿标为完成文件。

## 7. 实施顺序与分支安排

按用户要求，本轮先评审方案，不开始重构。

确认后：

1. 在真正有提交记录的 `repository` 中创建 `codex/cad-translation-refactor`。保全并记录当前未提交工作作为基线，不从旧 HEAD 丢掉已有改进，也不把它们冒充本次重构成果。
2. 固定测试用的源码与实际加载 DLL 版本，避免修改代码却运行另一版插件。分支测试使用独立产物，不立即替换日常部署。
3. 先处理文本校验不一致与结构失败定位，消除已知高成本阻塞。
4. 接入任务恢复与局部修正，再根据实测优化布局计算和重复打开／渲染。
5. 用稳定后的实际入口覆盖重写 skill，完成代表图对照后再考虑合并与部署。

不做通用 MCP 平台、全类型 CAD 适配、新 OCR 引擎或算法整体重写。共享中立基础设施，保留两种模式不同的内容修改与质量标准。

## 8. 验证与保留条件

复用现有测试和代表图，只增加与本轮实际缺陷对应的测试：

- 文本案例：图号紧邻数字、真实改数仍拒绝、MText 控制码、尺寸／数量语义、完整技术名词。
- 结构案例：不改文字另存对照、匿名块匹配、真实几何移动／删除仍能检出。
- 恢复案例：局部译文错误不重做好批次；检查失败能重查既有候选；局部修正不改源文和邻接合格区域。
- 真实图：DWG11 作为复杂阻塞样本；已有工艺图、双语表格和替换图作为回归样本，覆盖两种模式与至少一次反向语言处理。

先复用批准译文比较原生处理和修正成本，再对代表图做新译文端到端运行。记录真实任务总耗时、各阶段耗时、自动修正次数、最终质量和是否无人工加工完成。单元测试通过不替代成品判断，导入成功不等于交付成功。

当前 9 月 10—11 日保存的 13 份常规导入结果中，8 份失败、5 份成功，但包含同一图纸的开发重试，不能当作用户任务成功率。跨夜重试累计时间包含等待，也不能直接当作算法运行时间。重构对照按同一输入任务聚合全部尝试，并分别展示等待与计算成本。

保留有实测收益的改动：质量不下降且时间减少，或少量增加时间换取明确的效果／完成率提升。质量相当却增加复杂度和耗时的改动撤回。不能只通过降低检查要求使通过数变多。
