# Bilingual pipeline

Preserve original entities and add target-only MText nearby. Never rewrite the Chinese/English original to hold both languages. Export model space and every layout, including all recursively referenced block definitions. Keep unused block-library definitions unchanged; record exclusions in `bilingual-scope.json`. Do not spend translation or fitting time on dormant definitions that have no placed instances. Existing equivalent inline text or a uniquely matched nearby translation is reused; codes such as HCQ2000 are not evidence of bilingual coverage. Title-block equivalence uses a bounded vocabulary (for example Design / Designed by), never fuzzy matching of equipment qualifiers, codes or quantities.

```powershell
python scripts/cad_translate.py export --source "source.dwg" --job "jobs/bilingual-001" --output-mode bilingual --source-language zh-CN --target-language en
python scripts/cad_translate.py prepare-translations --job "jobs/bilingual-001"
# For Chinese→English, review exchange/bilingual-inline-candidates.jsonl.
# If complete inline pairs exist, rebuild the worklist with only confirmed handles:
# python scripts/cad_translate.py prepare-translations --job "jobs/bilingual-001" --existing-inline-handles "AB,CD"
# Return target-only translatedText in exchange/translated-batches/*.jsonl.
python scripts/cad_translate.py assemble-translations --job "jobs/bilingual-001" --translated "jobs/bilingual-001/exchange/translated-batches"
python scripts/cad_translate.py import --job "jobs/bilingual-001" --translations "jobs/bilingual-001/exchange/translations.output.jsonl"
python scripts/cad_translate.py audit-summary --job "jobs/bilingual-001"
```

Chinese→English preparation lists possible inline bilingual originals separately. Before translating, inspect these current-drawing candidates and confirm only complete Chinese/English equivalents with `--existing-inline-handles`. Codes, units or partially translated sentences are not complete pairs. Confirmed originals stay in the manifest and native source-preservation checks but leave the model worklist; assembly preserves protected tokens and supplies their existing English for native reuse. The review is bound to the source hash and entity hashes, not historical translations. Unconfirmed candidates follow the normal translation path. Worklist rows with `termMemberIds` represent a complete Chinese term from adjacent single-character entities: return one complete target such as `Stearic Acid` for 硬脂酸 or `Polymer` for 聚合物, not English syllables per source character. Assembly retains all member records; import creates one shared target without changing the originals. `bilingual-term-groups.json` binds grouping to the current source. Detection is conservative (2–12 unformatted, aligned single characters with matching owner/style/height and no separating boundary); do not assume arbitrary fragmented MText or rotated text has been grouped. Review meaning even when assembly marks a record approved; approval is not proof of semantic correctness. English→Chinese uses `--source-language en --target-language zh-CN`; Spanish→Chinese uses `--source-language es --target-language zh-CN`. Chinese additions use a Chinese-capable font. Source fonts, contents, locations and properties must remain unchanged.

For independent equipment, material and parameter schedules (including a numeric index column plus one translated description/value column), preserve the entire original table and create a full-size target-language copy in continuous whitespace inside the drawing frame. Try left, right, above, then below; allow a larger gap to clear adjoining title blocks. Copy row heights, column widths, cell order, line properties and unchanged codes/numbers. Translate only the copy's natural-language text, fitting it within its original cell; retain source-sized text where possible and wrap or reduce text height only when needed. Never shrink the whole table. Shared frame lines are copied only over the table's extent. Title blocks, company/signature panels and ordinary labels are not duplicated. Existing linked target tables are reused on a second pass.

The native copy path currently supports unrotated independent line-grid schedules with DBText/MText in model/paper space. Unsupported objects, unreadable members, nested definitions, incomplete grids or insufficient full-size whitespace try an aligned translation block outside the grid and record the reason; if that group also cannot fit readably, retain the normal unresolved/local-review path. Optional topology reads tolerate null, invalid, erased or foreign-database ObjectIds; required source-text reads remain explicit failures, not silent omissions. Missing polyline vertices invalidate the whole boundary: never bridge surviving vertices into invented table edges; retain readable object bounds as an obstacle. Native AutoCAD Table objects require specific coverage/manual review. A fallback is not evidence that the preferred table-copy strategy ran: inspect `bilingual-table-layout.json` and the rendered table before acceptance. For access failures, inspect `bilingual-object-access.json` (bounded examples) and `command-diagnostic.json` (stage, available object context, stack and loaded DLL fingerprint). Compare the deployed DLL before blaming proxy objects or fonts; a custom-object warning or `processedRecords=0` alone does not locate the failure.

Plan bilingual reading groups before individual labels. Aligned, adjacent explanation lines and long paragraphs form one translation block: preserve reading order, a common left edge, consistent readable height and row spacing. Reserve the entire block in nearby continuous whitespace, trying below, above and either side, with wrapping based on measured target widths. Include intervening source numeric lines in the occupied source envelope; do not scatter F1/F2/T1/T2 definitions around it. Avoid grouping unrelated captions across grid/process boundaries, layers or rotations. Existing equivalent bilingual content is reused.

When a table copy cannot be made, plan one ordered target block outside the original grid using the same four-side whitespace search. Keep each translated row/cell in source reading order with a common left edge and font height. Group reservations include projected block-instance text. If no continuous readable area is found, record the group and reason for local review; do not claim that the table-copy strategy ran. Review the entire translated group with its original, including long labels, numeric fields and row associations.

Placement measures the target text's real unwrapped MText width at each candidate scale. XY nearby labels first try source-height and 70%-height normal-width text at at most 16 adjacent positions. For rotated text, generate positions using the rotated footprint and compensate the insertion anchor; evaluate wrap widths along the text direction. Otherwise use the existing single-line, wrapped-width and width/height fitting strategy. Wrapping is conditional, never globally disabled or applied merely because the Chinese box is narrow. New target bounds combine native extents and padded font metrics: neither alone proves clearance. Failed XY labels can use bounded nearby obstacle-edge gaps inside the same allowed region. Emergency candidates use the same containment, boundary and protected-geometry checks as ordinary placement; they cannot bypass checks to reduce the unresolved count. This does not widen cells, move originals or trigger another whole-drawing run. Small but readable text remains a visual judgement, not a new universal minimum-height gate. Non-XY planes and nested block instances require specific placed-world review; a copied rotation is not proof of correct 3D placement.

When model/paper space and inserted block definitions both contain text, project occupied bounds through every direct/nested block-instance transform before choosing a position. Update those projected bounds after every addition so text that is collision-free in separate local definitions cannot overlap in the final visible layout.

During review, specifically compare short labels such as flow directions, cabinet names and drawing titles. Prefer single-line short labels when horizontal whitespace permits. A readable unnecessary wrap may be disclosed as a minor warning instead of forcing another job; fix it when a cheap local adjustment is available. Long equipment names may wrap when the available region genuinely cannot hold the measured single-line form safely. The bilingual branch independently accepts `passed_with_warnings` visual reviews for cosmetic issues only; missing additions, altered originals, incorrect associations and serious obstruction remain blocking.

`bilingual-pairs.json` records source handle, target handle, added/reused decision and bounds; `group-member` entries share their term leader's target, not additional translations. `bilingual-term-placement.json` records these groups. New nearby translations carry `AGICO_CAD_BILINGUAL` XData linking the original handle and original-text hash; reuse still checks the requested target text and the current original. This preserves pairing when collision avoidance places a translation beyond the neighbor-search radius. Saved output is reopened: original text/properties/geometry must match, associated target handles must exist, and non-text structure must be retained. A second pass over an already translated drawing must add zero duplicate translations. When a deployment still processes large dormant block libraries, check `bilingual-scope.json` and its loaded runtime path/module ID before retrying translation; local source edits do not prove that another service loaded the new DLL.

Relevant artifacts: `bilingual-native-check.json`, `bilingual-structure.json`, `bilingual-layout-audit.json`, `bilingual-language.json`, `bilingual-final.json`. No replacement residue gate or prose composition is used. Unplaceable labels remain unchanged in `bilingual-unresolved.json`, with nearby text, occupied bounds, placed-instance coordinates and `placement`: the actual allowed region, first-rejection counts and at most 18 candidate examples (up to three per reason). Examples record rotation, size, conflicting bounds, resolvable entity handles or boundary endpoints. A null handle may identify a reserved slot; counts are not a complete collision history. Inspect this evidence before changing the placer or rerunning the drawing. The saved-layout report reuses the already-open candidate to measure target/neighbor text bounds and flags local overlaps, region overflow, expanded saved bounds and small text; `layoutReviewRecordIds` points to affected details. These are visual-review pointers, not a separate hard gate or proof of complete world-space geometry/row association. Every fallback must avoid original and added text. Use `bilingual-review-windows.json` for readable world-space source/candidate details, then finish with the existing hash-bound `bilingual-visual-review.json`. Use the same-job [resume and correction commands](recovery-workflow.md) for retained candidates and existing target layout defects. Report total time across every retry and distinguish approved-translation reuse from fresh translation.
