# Bilingual pipeline

Preserve original text, properties and geometry; add target-only MText. Export model space, every layout and recursively placed block definitions. Leave dormant block-library definitions unchanged and record their exclusion in `bilingual-scope.json`. Inside block definitions, variable `AttributeDefinition` entities are templates, not drawn text: translate their visible `AttributeReference` instances instead. Invisible attributes are also excluded from bilingual additions. Constant visible attributes remain eligible.

```powershell
python scripts/cad_translate.py export --source "source.dwg" --job "jobs/bilingual-001" --output-mode bilingual --source-language zh-CN --target-language en
python scripts/cad_translate.py prepare-translations --job "jobs/bilingual-001"
# Review current-drawing inline candidates before confirming complete pairs:
# python scripts/cad_translate.py prepare-translations --job "jobs/bilingual-001" --existing-inline-handles "AB,CD"
# Consult references/cement-industry-glossary.md for current worklist terms (SKILL.md).
# Write target-only translatedText to exchange/translated-batches/*.jsonl; review term consistency before assembly.
python scripts/cad_translate.py assemble-translations --job "jobs/bilingual-001" --translated "jobs/bilingual-001/exchange/translated-batches"
python scripts/cad_translate.py import --job "jobs/bilingual-001" --translations "jobs/bilingual-001/exchange/translations.output.jsonl"
python scripts/cad_translate.py audit-summary --job "jobs/bilingual-001"
```

For Chinese→English, `bilingual-inline-candidates.jsonl` lists possible existing pairs. Review visible wording across formatting and confirm only complete equivalents using current handles. A Latin word, similar wording or a repeated two-column arrangement is candidate evidence, not proof of a translation. Confirm meaning, equipment qualifiers, direction and protected parameters as well as spatial association. Decimal points, signs and code separators must survive comparison (`1.5` is not `15`, `-20` is not `20`). Confirmed inline pairs stay in preservation checks but leave the translation worklist, bound to the current source/entity hashes. When a nearby complete counterpart is semantically verified, keep its wording in the target record instead of introducing a synonymous new translation; native reuse then checks its association. Native reuse requires the complete target wording or a bounded title-label equivalent; it cannot learn semantic equivalence from position alone. Do not approve partial English such as `Bag Filter` for `精密袋滤器` / `Fine Bag Filter`. For other directions, set explicit language flags; Chinese additions need a Chinese-capable font.

Rows with `termMemberIds` combine adjacent character entities into one complete term: translate the whole term, not syllables per entity. `bilingual-term-groups.json` binds the grouping; assembly retains all members and import creates one shared target. Review meaning even when a record is approved.

## Existing bilingual content: skip before translation and layout

Apply this rule to scattered labels, multi-entity paragraphs, chart/diagram text and tables. Review the meaningful object or group in the current source drawing, including separate nearby text entities. If it already presents the source and requested target languages with a clear correspondence, preserve it and skip translation, duplicate additions and layout. Record it as existing bilingual content, not a newly translated item. Codes, units, model names, a lone English word or an unrelated neighboring label do not establish bilingual correspondence. A different language pair does not satisfy the requested pair.

For title blocks, the user's accepted example is a bilingual field template: 比例/SCALE, 页数/TOTAL, 图号/DWG. No., 日期/DATE, 工程名称/PROJECT, 子项名称/SUB-SECTION, 图纸名称/TITLE and design/check fields. Preserve this table as it is and never create a translated copy of it. A filled-in value that is still source-only (for example 仓壁结构图) is not skipped: add its target text in place, directly above or below that value and inside its own cell, so the field becomes bilingual without touching the rest of the table. This explicit title-template rule overrides the former requirement that every language-bearing cell have a translated value; it does not make an ordinary data table bilingual merely because its headers contain English.

For other partially bilingual content, skip the verified bilingual units and process the remaining monolingual content according to its group rule. When a table still requires a complete target-only copy, reuse correct existing target wording in that copy rather than adding a third version. Do not mark a monolingual entity as an inline pair or fabricate a counterpart to force a skip. The existing `--existing-inline-handles` interface approves complete mixed-text entities only; it is not a whole-template exclusion switch. A whole-template skip must be represented explicitly in the execution path before claiming that it was applied.

## Choose the right group

Recognize complete tables in a common parent coordinate system after projecting nested block linework. Require real columns: at least one row band has two cells sharing a vertical side, with enough text-bearing cells to distinguish a table from dense structural linework. Reject sparse large cell grids and extreme sliver cells from orthographic equipment drawings. A stack of single-column signature fields or equipment frames connected by process lines is not sufficient. Header and body belong to the same table; row-height changes do not justify splitting them. Separate an adjoining title/signature table only at real cell boundaries with positive field evidence, never through a merged cell.

Use these layouts:

- **Tables, including title blocks:** apply the existing-bilingual skip rule first, including its title-template exception; preserve skipped tables whole and create no translated copy. Then use this order of preference:
  1. **Aligned target-language column — the standard.** When the grid already carries a target-language column, or a bilingual header pair such as `序号 / S.No.` with `BUILDING NAMES` beside `建筑名称`, keep the original grid, row numbers and column widths, and write each translation into that column on its own row. The shared row number is the authoritative pairing: one number, one entity, both languages on that line. Never shift a translation onto a neighbouring row. Leave numbering, elevations, areas, scales, units and other non-language columns exactly as drawn.
  2. **Fill missing cells only.** Where a bilingual header or an existing target column already covers most rows, translate only the cells still lacking target text, each inside its own cell. A cell lookup that misses (a label sitting between grid lines) means "no counterpart", never an exception.
  3. **Full target-only copy.** Only when the table has neither a usable target column nor any target text: retain the original and copy the complete grid with target-only text. The accepted threshold for "already bilingual" is at least 40% of the region's text entities carrying real target language; codes, units, model names, numbers and a lone English word never count.

  Never add a suffix beside the original inside a cell even when the cell has spare room, and never replace a row with an unframed text list. Preserve merged cells, row/column sizes, numbering, values, units, codes and line properties. Use reviewed existing target wording where correct. Do not exclude cells of a required copy with `--existing-inline-handles`, which preserves an entire mixed string instead of producing target-only copy text.
- **Single-column signature fields:** keep local source/target association. Recognize 日期/签名/实名/专业 as well as existing design/check fields. Rotated labels remain eligible for local translation when their frames are not a real table. Keep each translated signature field inside its own cell; try the original orientation first, then horizontal target text at readable height when the rotated translation is too long. Keep the original unchanged and do not spill the target across adjacent signature cells. An unfit field needs explicit layout repair, not silent omission or an ambiguous cross-cell label.
- **Short legends and code definitions:** keep row-by-row association in an aligned same-row target column. Do not turn them into prose panels.
- **Prose and substantial notes:** recognize the complete original block across individual text objects; preserve headings, numbering, paragraphs and reading order. Pair each source block with its own target block: several note blocks on one sheet remain several independent source/target pairs and are never consolidated into one shared translation area. Reserve a single aligned target block whose layout envelope has the same width as the original block, with a small native measurement allowance inside it. Start at the original readable text height; wrap and let the block grow vertically. Do not widen, narrow, split into columns or scatter rows to fit. Place the whole target block directly below the source block as a reading-order continuation (user-accepted reference 2026-09-22): the target's left edge aligned to the source block's left edge, one consistent vertical gap between the two blocks, and the block mirroring the source structure in order — translated heading first, repeating the source heading's own alignment so a centered heading stays centered over the target block, then each numbered item carrying its original number, one translation per item, never merged or renumbered; a wrapped item's continuation lines align under that item's text, not under the number. Use one consistent target style (font treatment, e.g. italic) for every target block on the sheet. Only when the space below is genuinely occupied may the block move to another empty position above, left or right, normally top-aligned. Prefer a position that leaves other views' linework untouched and accept a linework-crossing position only when no linework-free candidate exists; this linework preference is panel-only — scattered short labels keep their existing text-only clearance rule and may cross lines. Search nearby whitespace beyond the closest frame edge before reducing text height. Do not merge unrelated text columns. Detail tags, view scales, elevation marks, weld symbols and leader dimensions belong to the drawing area rather than to a note block: leave them exactly as drawn and preserve their emphasis colour.

For copied tables, keep the complete grid unscaled and try only positions immediately adjacent to the source with a modest gap. A tall table first moves horizontally toward the containing sheet's interior, then to the opposite exterior side. A wide table first moves vertically toward the sheet interior, then to the opposite exterior side. If both positions on that axis are blocked, try the two immediately adjacent positions on the other axis; otherwise report an unresolved placement. Do not jump to a distant sheet margin or shift a side copy far up/down merely to retain a preferred direction. A table crossing the nearest sheet border is permitted when its complete copy remains clear; evaluate the full destination against original/new text, engineering linework and protected objects, other table/signature grids including empty cells, reserved translation blocks and other sheets. Keep original objects and plot settings unchanged. Outside-frame placement is not a reason to shrink or detach the group.

The native grid path handles axis-aligned Line and Polyline grids with DBText/MText, unequal rows and merged cells; rotated text can be copied when native fitting proves it stays inside the copied cell. Pure nested grid blocks can be copied with their transforms intact. A real table with unsupported/mixed block members, unreadable grid entities or unfit target text remains a complete-table repair with an explicit reason and affected members. Never replace it with an unframed text list or count its missing cells as complete. Resolve the specific supported conversion/repair before delivery; do not fabricate grid boundaries or clone unrelated engineering objects. Native AutoCAD Table content still requires explicit extraction/copy coverage.

Inspect `bilingual-table-layout.json` for group membership, chosen strategy, destination and rejection reasons. Check actual source/candidate pairs: a recorded `note-block`, successful reservation or low unresolved count is not proof of correct classification or full-table coverage. Repair a misplaced group together, without retranslating valid content solely for layout.

Treat this inspection as a gate, not a review note. Print every table's `strategy`, `memberCount`, `missingRequestHandles`, cell counts and rejection reason, and assert each `strategy` against whether that region actually carries target text: a region with no target text must not be reported as `existing-bilingual-table`, and a required copy must not degrade into in-place labels. A parse that yields nothing, an absent field, an empty result read as success, or a count taken from a different artifact is a failed verification — re-read the file and resolve it before continuing. Silence is never a pass, and the time budget never authorizes skipping this gate.

The recorded strategies are the audit trail of this decision: `table-copy` means the whole grid was cloned (only acceptable for a table that had no target text at all), `existing-bilingual-table` / `cells-already-bilingual` means the table was preserved and only its missing cells were released for in-place labels, `existing-neighbor` pairs a source to a target that already existed in the same cell, and `table-copy-unresolved` keeps the affected members for repair. A run that clones a bilingual table, or that reports a non-zero unresolved count, is not finished.

Practical failure classes seen in a whole-drawing run, to check before another attempt:

- Reading block-attribute values inside the placement path aborts the core console with exit -1 and no managed traceback. Judge template content by entity type and by exporter-reported text only.
- A `First()`-style cell lookup throws when a text centre falls between grid lines; use a tolerant lookup and skip the miss.
- Releasing every member of many failed tables at once floods the placement search and makes the run slow or fatal; release only the members that truly lack a target.
- A sparse pseudo-table group (no changed requests or fewer than two texts) must release its members before skipping; otherwise group planning blocks the text for a copy that never happens and the run ends in `group-placement-unresolved` with no decision trace in `bilingual-table-layout.json` (fixed in `1ad49e5`).
- A stale `artifacts/candidate-binding.json` makes `import` resume the previous staged candidate instead of running the corrected layout; move it aside for a corrected run.
- Run long stages through the hidden launcher (`scripts/run_hidden.vbs`) so no console window reaches the user's desktop, and remove the one-shot scheduled task when the stage ends.

## Fit and associate

Ordinary labels stay clearly associated with their source. Before accepting wrapping, measure the complete unwrapped translation and search nearby source-edge and obstacle-edge aligned positions at readable height; a failed centered single-line attempt does not establish insufficient space. When local single-line positions are blocked, test broader target-measured wrapping and modest width fitting before accepting a word-per-line column. Do not inherit a narrow Chinese box as the final English width. Keep genuinely necessary readable wrapping nearby rather than forcing a remote single line. Dense linework must not crowd useful block-edge anchors out of the bounded search. Review unnecessary word-per-line columns as well as reduced-height text at readable scale. Position/scale search thresholds belong to the placer, not manual per-drawing tuning.

Check target bounds against all original and newly added text, including dimension values, in the final placed view. Text-to-text overlap remains blocking. For ordinary labels, drawing lines, frame edges and engineering linework are not hard collision obstacles: prefer clear nearby space, but allow crossing lines when text remains readable and clearly associated. Signature cells retain field ownership, and complete table destinations must also clear other table/signature grids, including empty cells. Never move or erase original geometry. Project text occupancy through every direct/nested block-instance transform and keep model/paper roots separate. Rotated/shared blocks require review of their actual instances; local-definition clearance is not world-space clearance. Apply text clearance to labels, tables, panels and fallbacks, together with their group-specific constraints; replacement-mode constraints are unchanged.

For any translation outside a frame, inspect source and target together and confirm complete, readable content and clear association. Crossing the frame line is permitted; avoid assigning a panel to an unrelated sheet or overlapping its text. Preserve original geometry and plot settings. Disclose that the existing print window or viewport may exclude outside additions and must include them before printing. This printing limitation alone is a warning, not failed translation. If the requested deliverable is a plotted PDF or an explicitly fixed print layout, verify inclusion in that actual deliverable instead.

## Evidence and repair

Use compact reports and selected records rather than dumping detailed audits:

- `bilingual-pairs.json`: source/target handles, reuse decisions and bounds. Shared term members reference one target. New targets carry `AGICO_CAD_BILINGUAL` XData; reuse still checks text and source hashes. A second pass over a translated input must add no duplicates.
- `bilingual-native-check.json`, `bilingual-structure.json`, `bilingual-language.json`, `bilingual-final.json`: reopened-candidate source preservation, structure, content and final binding. This branch does not use replacement residue/composition gates.
- `bilingual-layout-audit.json` and `bilingual-unresolved.json`: overlap, small text, distant association and placement failures, with bounded rejection examples. These point to visual checks; distance alone is not rejection, and table/panel associations are judged as groups.
- `bilingual-review-windows.json`: placed-world detail windows. Use these and current target bounds to select readable source/candidate evidence.
- `bilingual-object-access.json` and `command-diagnostic.json`: bounded access failures, stage/context and loaded DLL identity. Check these before blaming proxies/fonts or changing the placer.

For saved layout defects, follow [same-test recovery and correction](recovery-workflow.md), then [visual review](visual-audit.md) with `bilingual-visual-review.json`. Missing additions, altered originals, misleading pairings and text-to-text overlap cannot be cosmetic warnings. Unsupported or unresolved coverage must remain explicit.
