# Bilingual pipeline

Preserve original entities and add target-only MText nearby. Never rewrite the Chinese/English original to hold both languages. Export model space and every layout, including all recursively referenced block definitions. Keep unused block-library definitions unchanged; record exclusions in `bilingual-scope.json`. Do not spend translation or fitting time on dormant definitions that have no placed instances. Existing equivalent inline text or a uniquely matched nearby translation is reused; codes such as HCQ2000 are not evidence of bilingual coverage. Title-block equivalence uses a bounded vocabulary (for example Design / Designed by), never fuzzy matching of equipment qualifiers, codes or quantities.

```powershell
python scripts/cad_translate.py export --source "source.dwg" --job "jobs/bilingual-001" --output-mode bilingual --source-language zh-CN --target-language en
python scripts/cad_translate.py prepare-translations --job "jobs/bilingual-001"
# For Chinese→English, review exchange/bilingual-inline-candidates.jsonl.
# If complete inline pairs exist, rebuild the worklist with only confirmed handles:
# python scripts/cad_translate.py prepare-translations --job "jobs/bilingual-001" --existing-inline-handles "AB,CD"
# Return target-only translatedText in exchange/translated-batches/*.jsonl.
python scripts/cad_translate.py assemble-translations --job "jobs/bilingual-001" --translated "jobs/bilingual-001/exchange/translated-batches"
```

Chinese→English preparation lists possible inline bilingual originals separately. Before translating, inspect these current-drawing candidates and confirm only complete Chinese/English equivalents with `--existing-inline-handles`. Codes, units or partially translated sentences are not complete pairs. Confirmed originals stay in the manifest and native source-preservation checks but leave the model worklist; assembly preserves protected tokens and supplies their existing English for native reuse. The review is bound to the source hash and entity hashes, not historical translations. Unconfirmed candidates follow the normal translation path. English→Chinese uses `--source-language en --target-language zh-CN`; Spanish→Chinese uses `--source-language es --target-language zh-CN`. Chinese additions use a Chinese-capable font. Source fonts, contents, locations and properties must remain unchanged.

For independent multi-column equipment, material and parameter schedules, preserve the entire original table and create a full-size target-language copy in continuous whitespace inside the drawing frame. Try left, right, above, then below; allow a larger gap to clear adjoining title blocks. Copy row heights, column widths, cell order, line properties and unchanged codes/numbers. Translate only the copy's natural-language text, fitting it within its original cell; retain source-sized text where possible and wrap or reduce text height only when needed. Never shrink the whole table. Shared frame lines are copied only over the table's extent. Title blocks, company/signature panels and ordinary labels are not duplicated. Existing linked target tables are reused on a second pass.

The native copy path currently supports unrotated independent line-grid schedules with DBText/MText in model/paper space. Unsupported objects, nested definitions, incomplete grids or insufficient full-size whitespace fall back to cell-local bilingual placement and record the reason. Native AutoCAD Table objects require specific coverage/manual review. A fallback is not evidence that the preferred table-copy strategy ran: inspect `bilingual-table-layout.json` and the rendered table before acceptance.

For single-column lists with one translated source per row, retain the side-column strategy: shared left edge and font height, source row order, and vertical row alignment. Measure the complete column inside the frame before reserving it. Do not merge unrelated fields into one ambiguous translation row. Existing equivalent bilingual text is reused. Review the entire copied table or translation column, including its outer borders, long labels, preserved numeric fields and row associations.

Placement measures the target text's real unwrapped MText width at each candidate scale. If that single-line width fits a collision-free nearby region, try it before any wrapped width. If it cannot fit without crossing a cell/frame, process geometry, equipment or neighboring text, allow controlled wrapping, then width compression and height reduction. Wrapping is conditional, never globally disabled or applied merely because the source Chinese text box is narrow. Test below/above/right/left positions and preserve a readable height floor. Rotated text retains its plane and orientation, but non-XY planes and nested block instances require specific visual verification; a copied rotation is not proof of correct 3D placement. Never move original text to create room.

When model/paper space and inserted block definitions both contain text, project occupied bounds through every direct/nested block-instance transform before choosing a position. Update those projected bounds after every addition so text that is collision-free in separate local definitions cannot overlap in the final visible layout.

During review, specifically compare short labels such as flow directions, cabinet names and drawing titles. Prefer single-line short labels when horizontal whitespace permits. A readable unnecessary wrap may be disclosed as a minor warning instead of forcing another job; fix it when a cheap local adjustment is available. Long equipment names may wrap when the available region genuinely cannot hold the measured single-line form safely. The bilingual branch independently accepts `passed_with_warnings` visual reviews for cosmetic issues only; missing additions, altered originals, incorrect associations and serious obstruction remain blocking.

`bilingual-pairs.json` records source handle, target handle, added/reused decision and bounds. New nearby translations carry `AGICO_CAD_BILINGUAL` XData linking the original handle and original-text hash; reuse still checks the requested target text and the current original. This preserves pairing when collision avoidance places a translation beyond the neighbor-search radius. Saved output is reopened: original text/properties/geometry must match, associated target handles must exist, and non-text structure must be retained. A second pass over an already translated drawing must add zero duplicate translations.

Relevant artifacts: `bilingual-native-check.json`, `bilingual-structure.json`, `bilingual-layout-audit.json`, `bilingual-language.json`, `bilingual-final.json`. No replacement residue gate or prose composition is used. Unplaceable labels remain unchanged and are listed in `bilingual-unresolved.json`, with nearby source text, occupied bounds and placed-instance coordinates. Inspect that evidence before changing the placer; do not guess a new cause and rebuild the whole drawing repeatedly. Every fallback must still avoid original and added text. The job fails rather than forcing overlap. Use `bilingual-review-windows.json` for native world-space detail windows; render matching source/candidate regions directly instead of enlarging overview crops. Finish with a hash-bound `bilingual-visual-review.json`. Report total test time across every retry, and disclose reuse of approved translations separately from fresh-translation timing.
