# 原生 DWG 操作与核验

本参考用于选择并实施原生 CAD 操作，不是某一份图纸的固定脚本。无需另一个翻译技能或第三方翻译服务。已有可靠原生工具可直接使用；没有合适工具时，在工作目录按以下契约编写小型 .NET 插件与辅助脚本。

目录：环境与保存隔离 → 提取与范围 → 翻译映射 → 排版与符号 → 保存后验收。

## 1. 环境与保存隔离

- 检查实际安装的 AutoCAD、`accoreconsole.exe` 和对应 `acdbmgd.dll`、`acmgd.dll`、`accoremgd.dll`。项目引用同一安装目录，程序集 `Private=false`；目标运行时与该 AutoCAD 版本匹配。已有实践环境为 AutoCAD 2025 / .NET 8，不能把路径或版本写死为通用前提。
- 纯原生提取、写回和批量核验优先 Core Console。视觉检查使用 DWG 原生显示；不要搭建 PDF 打印或转换流程。
- **每一次 CAD 打开，包括提取和核验，都打开工作副本。**Core Console 会话及退出行为可能写入其输入文件，`QUIT _NO` 不能充当源文件保护措施。
- 为本次任务建立独立目录，例如 `work/cad/<job-id>/`。源文件只供普通文件复制和哈希读取。CAD 输入副本、候选输出、核验副本、最终交付路径互不相同；不覆盖源文件。
- 插件使用原生 `Database.SaveAs` 写到不同路径的候选文件。关闭会话、等待进程完全结束后才复制为最终交付文件；不要用仍被 CAD 打开的路径作为最终交付。
- 一次构建插件，复用当前任务的提取清单。写操作在事务中完成；任何未处理失败都回滚。写独立的成功/失败状态文件，并检查输出文件及状态内容，不能只检查进程退出码。
- 每次重试读取当前副本与当前映射。原始源文件 SHA-256 在开始和交付前一致，才证明保护成功。

## 2. 完整提取与图纸范围

遍历 `BlockTable` 中模型空间、纸空间和所有非外参 `BlockTableRecord`，不要只处理屏幕中选中的对象。实体类型与内容接口如下。

| 对象 | 需读取/写回的内容 | 关键区别 |
| --- | --- | --- |
| `DBText` / `AttributeDefinition` | `TextString` | 保留高度、宽度因子、对齐和旋转 |
| `MText` | `Contents` | 同时记录纯显示文字与原始格式串 |
| `BlockReference` 的 `AttributeCollection` | 各 `AttributeReference` 的文字 | 定义与插入实例分别覆盖；多行属性按实际 API 保留格式 |
| `MLeader` | MText 内容或其块属性内容 | 修改 MText 副本后赋回 `MLeader.MText` |
| `Dimension` | 非空 `DimensionText` 覆盖 | 自动测量值不是译文，不破坏 `<>` 占位符 |
| `Table` | 各单元格实际文本/文本内容项 | 记录行列、合并关系；不要把块内容或字段当普通字符串 |

普通 `Leader` 的注释还需沿引用找到文字实体。字段表达式、动态块可见性、代理对象、文字轮廓及嵌入图片分别检查，原生文本数量不能证明这些对象没有文字。

每条记录至少保留：`handle`、对象类型、`slot`（如表格行列）、原始内容 `raw`、解码后的显示内容、所属块/空间、属性实例的 owner/tag、图层、字体/大字体、插入/对齐点、旋转、文字高度/宽度、包围盒。多次嵌套的可见实例另记完整变换矩阵，块定义的文字只写回一次。

解码 `\U+XXXX` 并区分 MText 控制串与显示文字。仅译可见内容；块名、图层名、属性 tag 等内部标识即使含中文也不能直接计作漏译或随意改名。尺寸自然生成的数值应保留。

同时记录非文字实体的类型、图层、实际几何参数及引用关系：线端点，圆心/半径，弧角度，多段线顶点/bulge，块插入点/比例/旋转等。只对比包围盒不足以证明几何未变。

外参需记录路径、加载状态、可见范围和文字覆盖缺口。默认不修改外部原文件，不自动绑定或炸开所有外参。需要纳入英文交付时，按用户授权范围对引用副本处理，并验证依赖；无法读取时明确说明缺口。

### 模型空间少于文件名张数

建立块引用图和图框清单，用图号、标题、尺寸、位置和实际内容核对。未引用块可能是旧版备份，也可能存有完整图纸组合；不能根据块名或文件名直接替换模型空间。

在单独检查副本中插入候选组合，检查图纸内容和重复/遗漏。若已证明它是用户所需完整组合，才在交付副本恢复。块定义存在非零 `Origin` 时，在原有块坐标下恢复通常需 `new BlockReference(block.Origin, block.ObjectId)`；使用世界原点可能使整体图纸偏移。仍须结合原有实例变换验证世界坐标。

保留原块内工程几何。恢复范围产生的模型空间引用变化与普通翻译的几何检查分开记录。不要对所有文件套用特定块名、图框名或固定张数。

## 3. 模型翻译与映射契约

按图纸专业、标题、上下文和阅读顺序形成翻译批次，由当前模型生成英文。程序不调用在线翻译或其他模型。词汇一致不等于孤立逐字替换；区分建筑/结构语境，如 beam、column、slab、reinforcement、foundation、finish、elevation 等。

先将同基线/旋转、相近字体高度、同栏内的碎片组成语义单元。遇到表格边线、跨栏间隔或不同注释区域立即分组；单字符标题只在确认构成同一标题时合并。保留所有组成实体与目标文本的对应关系。

清单同时保留未翻译但需原样保留的条目。译文映射以 `handle + slot` 定位，并绑定输入副本的源文件指纹；每条包含 `expectedRaw`、`target`、处理类别和布局计划，具体遵循 [数据契约](data-contracts.md)。表格 row、column、contentIndex 统一零基，提取和写回使用同一契约。缺少索引声明的旧清单须由提取器确认或重新提取，不能猜测。写回前逐条比对原文。源文不匹配、重复目标定位、空译文或无法解释的未覆盖记录均需处理，不能沿用旧映射强行写入。

合并重排的记录另含：全部源 handle、所属块、继承属性的代表实体、原有注释区矩形、坐标系/旋转、目标内容、目标字体、字号及排版策略。程序根据这些明确参数执行，而不是从某份图纸复制固定坐标。

数字、符号和格式串用保护标记或独立字段维护，并检查源/目标对应。允许正常的中英文单位表达转换，但不能把 `C30`、`HRB400`、`Φ12@200`、标高符号或标准编号当词汇改写。原文技术矛盾及标准号疑似错误不擅自修订。

检查中文之外的非目标语言。终验残留统计针对可见文字及确实待译内容，不能仅靠 CJK 正则；公式、代码和项目标识按语境保留。

## 4. 排版与工程符号

### 可用空间与字号

- 原始文字包围盒记录源位置，不一定等于英文可用空间。先识别原有表格单元格、注释栏、邻近留白和工程几何，建立允许排版的区域。
- 在文字本地坐标系内量空间。旋转为 `θ`、轴对齐包围盒宽高为 `w,h` 时，`abs(cosθ)*w + abs(sinθ)*h` 可作轴向投影的估计；任意角度时须用真实区域的逆变换判断，不能将投影估计当成精确容纳矩形。90 度文字尤其不能拿世界坐标的窄边直接挤压。
- 优先准确而简洁的英文、换行和段落重排，再有限调整宽度因子/字号。依据出图比例确定可读字号底限；无法确定比例时以源字号和原生视图可读性为基准，不自动缩成原字号的四分之一来通过边界检查。
- `DBText` 改样式/宽度后调用 `AdjustAlignment(db)`；保留原有对齐锚点。`MText` 设定允许宽度后读取 `ActualHeight`，在可读字号范围内迭代拟合。同一注释栏的段落字号、行距、编号和缩进保持一致。
- 新建 `MText` 先 `SetDatabaseDefaults(db)`，再 `SetPropertiesFrom(sourceEntity)`；否则嵌套块中的颜色/图层可能变成默认值。保留所需旋转、位置及附件点。不要改共享原样式而影响未翻译的符号文字；必要时创建独立英文样式。
- 表格保留行列边界、合并、线条及工程数据；注释不得跨栏或遮挡尺寸、引线、钢筋和图形。

### SHX 与 TEXT → MTEXT

检查原字体、大字体及实际字形。Arial / Arial Narrow 适合一般英文；含工程专用字形的片段需保留对应 SHX 或经过验证的等效原生表示。不能把钢筋等级字形一律换成直径符号。

TEXT 的旧 `%%nnn` 代码移入 MTEXT 后可能显示为字面代码。已确认使用对应 TSSD 字体并经原生显示核对时，`%%130`–`%%134` 可按字体字形编号转换为 `\U+0082`–`\U+0086`；这不是适用于全部字体的 Unicode 钢筋符号表。字符仍由相应 SHX 解释。

已确认原文 `%%1402%%141` 表示上标 2 时，可改为 MTEXT 原生格式 `{\H0.7x;\S2^;}`；`%%1403%%141` 同理。`%%%` 只有确认原图实际显示一个百分号时才转换为 `%`。保留直径、正负、度、上下标及字段结构；直接清理所有百分号代码会毁坏技术含义。

此检查也适用于**原对象已经是 MTEXT**的情况：先查看原图真实显示并记录原格式，不能因对象类型是 MTEXT 就假设旧码有效。已确认字形/上标语义时，在候选文件中使用验证过的 MTEXT 原生表示，并对照显示；若原图本身已字面显示旧码，则结合字体定义及图纸语境确认含义后修复。无法确认含义时保留原始码、记录 `symbol_unverified` 阻塞，不将该项计为通过，也不猜成普通数字或直径符号。

### 原生写回示例

以下为事务内已有 `db`、`tr`、`id`、`expectedRaw`、`target` 的片段：布局计划和符号转换已在此前完成。它用于说明锁层与属性继承，不能代替完整提取/拟合程序。

```csharp
// forceOpenOnLockedLayer=true；不需要临时解锁再还原图层。
var entity = (Entity)tr.GetObject(id, OpenMode.ForWrite, false, true);
if (entity is DBText text)
{
    if (text.TextString != expectedRaw)
        throw new InvalidOperationException("Source text changed");
    text.TextString = target;
    text.AdjustAlignment(db);
}
else if (entity is MText note)
{
    if (note.Contents != expectedRaw)
        throw new InvalidOperationException("Source text changed");
    note.Contents = target;
}
else
{
    throw new InvalidOperationException("Use the entity-specific writer");
}

// 确认合并重排时，新对象继承代表源实体的属性。
// using var replacement = new MText(); // 未入库对象失败时应释放。
// replacement.SetDatabaseDefaults(db);
// replacement.SetPropertiesFrom(entity);
// 按布局计划设置字体、位置、旋转、附件点、Width 和 TextHeight；
// 插入正确的 BlockTableRecord，登记新对象，再逐步拟合 ActualHeight。
```

`UpgradeOpen()` 单独使用可能触发 `eOnLockedLayer`。所有译文写操作仍属于同一受控事务；不捕获异常后静默继续并称为成功。

## 5. 保存后的验收与效率

必须从已经保存并关闭的候选 DWG 新建核验副本，在新会话中重新提取；不能把内存中的已修改内容当作保存成功的证据。

内部核验清单包括：源/目标文字覆盖、按类型写回失败、图纸范围、非目标语言残留、工程数值与符号、字段、字体依赖、非文字几何变化、所有有意范围变化，以及最终源文件 SHA-256。合并后文本对象数量可以变化，用来源映射证明覆盖，不要求两边文字实体数相等。

文字几何检查在本地坐标和完整块实例变换中执行；重叠判定结合原注释区域和源图实际布局。对照源 DWG，逐张检查全图和标题、技术说明、表格、钢筋详图等密集区域的原生视图或直接原生截图。原生截图可以临时保存为 PNG，不能通过 PDF 转换取得。文本正确与视觉正确是两项独立验收。

没有可控桌面视图时，可检查当前 AutoCAD 是否提供 `PublishToWeb PNG.pc3` 等原生 PNG 设备。用 `PlotSettingsValidator` 查询设备实际支持的介质/像素尺寸，再按图框窗口和密集区域窗口直接输出临时 PNG；设备名及尺寸以本机查询结果为准。使用独立 `PlotSettings` / `PlotInfo.OverrideSettings`，避免修改图纸布局设置。先确认小范围输出及符号显示可靠，再批量输出各图；PNG 只用于内部核验，不交付。

缺少原生可视检查手段时，不能仅凭 JSON 包围盒声明“排版完全核验”；继续解决可视检查能力，仍无法解决则如实披露限制。嵌入图片、轮廓文字或代理内容没有被提取时，不能报告整图无漏译。

插件构建、整图提取和完整对照尽量各做一次。局部修正先复查受影响区域，最后对保存的最终候选做整体核验；新失败或变化才触发额外重跑。重复文字在本次任务中按语境复用译文；测试必须使用新工作副本和新映射。

通过验收后只复制最终 `.dwg` 到交付目录。JSON、日志、构建产物、截图及状态文件留在工作目录，不作为交付附件。不要承诺某次示例的固定张数、实体数或零残留统计适用于下一份图纸。
